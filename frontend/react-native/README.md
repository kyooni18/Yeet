# Yeet frontend

Read `../../app/ui/ContentView.ui` first. Layout specifications are design documents for humans and AI agents; normal React Native components implement them. No `.ui` file is loaded at runtime.

## Develop

Node.js 22.13 or newer is required by Expo SDK 57.

```sh
npm ci
npm run ios
npm run android
npm run web
npm run typecheck
npm run lint
npm run export:web
npm run export:native
```

Expo Router routes under `src/app` wrap the `ContentView` implementation. iOS/iPadOS and Android use the same components with native safe area, keyboard handling, document picker and clipboard. Native project directories are generated by Expo; configuration lives in `app.json`. A device connects to an existing Rust `yeet remote` server using its reachable HTTPS origin and access key. Native authentication uses the server-issued cookie; the access key is never persisted. Verify authenticated HTTP and WebSocket behavior on devices before distribution. Native passkey enrollment is not yet provided; use the compatibility browser client for enrollment.

Web must run on the Remote server's origin to use its HttpOnly cookie. To embed the Expo export without changing the compatibility default:

```sh
npm run export:web
cd ../..
YEET_FRONTEND_DIST=frontend/react-native/dist cargo build
./target/debug/yeet remote
```

Open the address printed by Remote and press Connect with that same origin. `YEET_FRONTEND_DIST` is an explicit build-time selection; omitted, Rust continues to embed `web/dist`. Remote remains workspace-neutral; each client selects its workspace/session. Standalone `expo start --web` supplies a UI preview; it does not proxy `/api` to Rust. Use the embedded export for full web integration.

For local macOS/Windows/Linux use `../desktop` (Tauri 2). That host talks directly to the existing Rust Harness through narrow commands/events, and asks for an existing absolute workspace path. Distribution requires the normal platform toolchains, signing and bundled Yeet runtime assets; see the desktop README.

The network client shares protocol, transport and streaming state with the compatibility web app through `../shared`. Platform code adapts storage, cookies, endpoint resolution, connectivity, uploads and desktop IPC. Rust owns all agent/tool/session/provider/filesystem business logic.

Filesystem browsing is deliberately shown as unavailable: the existing core contract has no browsing endpoint. Local Harness attachment uploads are unavailable; Remote clients use the existing Rust attachment API. The compatibility web UI remains available while rich Markdown, native passkeys and desktop attachment parity are developed.

## Verification

`npm run typecheck`, `npm run lint`, web/native exports and `npx expo-doctor` validate source and SDK configuration. The focused browser tests reuse the existing Rust protocol mocks. From repository root after exporting web:

```sh
./web/node_modules/.bin/playwright test --config frontend/react-native/playwright.config.mjs
```

Native bundle export confirms bundling, not device execution, signing or store readiness. Desktop Cargo checks validate the host on the current platform; Windows/Linux packaging needs those toolchains.
