Yeet audit — November 11, 2026

Reviewed commit `4c2bccb07cba574c74f9804fe2e0606d9085e10c`. This is a findings report; application code and design specifications were not changed. P1 means high-priority correctness or data-loss risk; P2 means a meaningful reliability, usability, efficiency, or verification issue.

The strongest findings are attachment submission failing after acceptance, drafts crossing session boundaries, and stale WebSocket callbacks affecting a replacement connection. Rust and provider-runtime unit tests are green, but they do not cover these complete client-to-server paths.

**1. P1 — Attachment submissions are acknowledged before the backend rejects them. Confirmed against an isolated Rust server.**

The active browser sends attachments through `ui_composer_action`. Rust's composer produces a Submit command containing `attachment_ids`, but the Remote composer handler forwards it directly to the background service. Attachment resolution only happens in the separate legacy `ClientMessage::Command` branch. The Harness rejects unresolved IDs.

The isolated probe uploaded a text file successfully (HTTP 201), submitted its ID through the composer, and received an `accepted_editor` effect followed by `backend_error: Remote attachment IDs must be resolved before backend submission`. The browser clears a matching accepted draft and its attachments. Thus an ordinary attachment submission fails while the editor can already be cleared. No model completion was invoked in this probe.

Evidence: [composer dispatch](/Users/kyooni18/Code/Yeet/src/remote/websocket.rs:879), [legacy attachment resolution](/Users/kyooni18/Code/Yeet/src/remote/websocket/socket.rs:375), [Harness rejection](/Users/kyooni18/Code/Yeet/Harness/service.rs:302), [editor clearing](/Users/kyooni18/Code/Yeet/web/src/app/composer.ts:173).

Recommended repair: resolve attachments for the prepared composer command before delivery, retain recoverable uploads on failure, and acknowledge editor acceptance only after the relevant validation succeeds. Cover the actual upload → composer → Harness path with one integration regression.

**2. P1 — Drafts and attachments are global instead of belonging to a session. Confirmed in the active browser UI.**

The Mün composer keeps one global `text`, `attachments`, editing flag, and stashed draft. It takes the destination context from the latest server projection without switching the local draft when that context changes. Navigating to another session or workspace therefore carries old text into the new context.

Browser reproduction: type “Only for session A,” apply a session-B transition, then press Send. The field still contains the A draft. The captured outbound action has `context.session_id: "session-b"` and `text: "Only for session A"`. Both laptop and phone probes reproduced the retained draft. Existing context-isolation tests also fail at their text assertions, independently of stale sidebar selectors.

Evidence: [global composer state and context selection](/Users/kyooni18/Code/Yeet/web/src/app/composer.ts:12), [existing behavioral regression](/Users/kyooni18/Code/Yeet/web/tests/composer-draft-context.spec.ts:40).

Recommended repair: associate the complete editor state with workspace, session, and unsaved-generation identity. Restore the appropriate draft atomically on context changes, including pending uploads and edit-last state. Reuse the existing behavioral tests with current UI selectors.

**3. P1 — Obsolete connections can change current connection state. Confirmed with a deterministic transport probe.**

`connect()` does not invalidate asynchronous discovery after `close()` or a newer connection attempt. Socket message handlers do not check that their socket is still current. The close handler stops the shared heartbeat before checking whether the closing socket is obsolete.

A controlled adapter reproduced three outcomes: a socket was created after closing a pending connection; closing an old socket removed the replacement socket's heartbeat (active intervals went from one to zero); and an old socket's snapshot was delivered to the application. Rapid workspace switches, network recovery, or repeated authentication retries can consequently mix stale state into the replacement connection or disable its liveness checks.

Evidence: [asynchronous connect](/Users/kyooni18/Code/Yeet/frontend/shared/remote/transport.ts:97), [unguarded message handler](/Users/kyooni18/Code/Yeet/frontend/shared/remote/transport.ts:266), [close handler ordering](/Users/kyooni18/Code/Yeet/frontend/shared/remote/transport.ts:328).

Recommended repair: give each connection attempt a generation, ignore stale discovery results and callbacks, cancel outstanding retry timers when superseding them, and scope heartbeat cleanup to the owning socket.

**4. P2 — Automatic nested instructions arrive after the action they govern. Confirmed by execution order; no model-quality benchmark was run.**

The agent dispatches and records all tool calls before `finish_tool_round()` discovers nested AGENTS.md files. A direct first edit under a restricted subtree can therefore happen before that subtree's instructions reach the model. Shell-based file access is not recognized by `touched_paths` at all: only `read_file`, `apply_file_edits`, and `outline` participate.

Evidence: [dispatch before round completion](/Users/kyooni18/Code/Yeet/Harness/agent.rs:480), [post-execution instruction loading](/Users/kyooni18/Code/Yeet/Harness/agent/tool_round.rs:132), [recognized tools](/Users/kyooni18/Code/Yeet/Harness/agent/nested_instructions.rs:61).

Recommended repair: discover applicable instructions before the first mutation. If new instructions were absent from the model request, return them and defer the mutation so the model can reconsider. Include session-working-directory instructions for shell workflows without pretending arbitrary shell commands can be fully analyzed.

**5. P2 — Background-tab buffering has no bound. Confirmed in the shared store.**

Every decoded message is appended to `eventQueue`; draining depends entirely on an animation-frame callback. When frames are suspended, incoming messages accumulate without coalescing or a byte limit. A paused-scheduler probe retained all 1,000 cumulative snapshots while scheduling only one pending frame. The recently added server replay limit does not bound this separate client queue. Browser throttling makes background tabs a relevant trigger; actual out-of-memory behavior was not measured.

Evidence: [queue and frame-only draining](/Users/kyooni18/Code/Yeet/frontend/shared/state/remoteStore.ts:281).

Recommended repair: separate state reconciliation from paint scheduling, or bound/coalesce replaceable messages while preserving discrete effects and sequence semantics. Resynchronize from a snapshot when a safe bound cannot be maintained.

**6. P2 — Shell output unnecessarily invalidates the application store. Confirmed with a notification-count probe.**

`shell_job` messages correctly dispatch to dedicated shell listeners, but `flushEvents()` still emits a new global snapshot for every nonempty batch. Ten shell-only batches produced ten global notifications despite no application-state change. The active client then updates its general reactive snapshot and runs its subscribers. This contradicts the UI specification's explicit requirement that shell output not invalidate unrelated views. The probe establishes excess notifications, not a claim that every DOM subtree fully redraws.

Evidence: [unconditional global emit](/Users/kyooni18/Code/Yeet/frontend/shared/state/remoteStore.ts:294), [shell-only dispatch](/Users/kyooni18/Code/Yeet/frontend/shared/state/remoteStore.ts:307), [active client subscription](/Users/kyooni18/Code/Yeet/web/src/app/state.ts:420).

Recommended repair: route ephemeral shell responses independently, or track whether a batch actually changed the application snapshot before emitting globally.

**7. P2 — The narrow-phone composer wraps Send onto its own row. Confirmed visually and geometrically.**

At 320 × 568 with the existing model and reasoning controls, Attach, Model, and Reasoning begin at y=453, but Send begins at y=501 and moves to the left edge. The composer surface is 308 × 189 CSS pixels, consuming roughly one-third of the screen before the keyboard opens. All individual controls satisfy the touch-height check, so the current test misses the row-layout regression.

Evidence: [control row](/Users/kyooni18/Code/Yeet/web/src/app/Chat.mun:557), [phone wrapping rules](/Users/kyooni18/Code/Yeet/web/src/app/remote.css:338), [captured phone layout](/Users/kyooni18/Code/Yeet/docs/audits/2026-11-11-mobile-composer.png).

Recommended repair: preserve the primary action's position and constrain the model/reasoning controls at the smallest supported width. Extend the existing phone-layout check to compare control-row coordinates and usable transcript space.

**8. P2 — The default browser suite mixes retired and active UI contracts. Confirmed by source and test execution.**

The shipped entry is `src/main.ts`, mounting Mün. The default Playwright configuration still includes tests requiring the previous React shell's `.remote-sidebar` and “Open sidebar” controls; the active shell uses `#sidebar` and “Toggle sidebar.” Those failures obscure real failures such as draft leakage. The broad laptop run was deliberately interrupted after repeated obsolete-selector failures; it was not a completed suite result.

Evidence: [active entry](/Users/kyooni18/Code/Yeet/web/index.html:13), [default test inclusion](/Users/kyooni18/Code/Yeet/web/playwright.config.ts:4), [obsolete navigation contract](/Users/kyooni18/Code/Yeet/web/tests/navigation-shell.spec.ts:14).

Recommended repair: migrate behaviorally useful tests to the active UI and remove or explicitly archive retired renderer-specific tests. Keep draft ownership, authentication, reconnect, and delivery behavior covered rather than merely deleting failing tests.
