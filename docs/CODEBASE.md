# Yeet codebase structure

Yeet keeps orchestration code separate from policy, persistence, presentation, and external I/O. A source file should have one primary reason to change. When a module starts accumulating a second independent responsibility, move that responsibility into a named child module instead of extending the parent indefinitely.

New or extracted Rust modules should normally stay below 1,200 lines including focused tests. The central `agent.rs`, `backend.rs`, and `tools.rs` coordinators are capped at 1,250 production lines; every Rust production module has a 1,700-line hard ceiling and every Rust source file has a 3,000-line absolute ceiling including tests. `RuntimeSource/src` TypeScript modules are capped at 1,200 lines. These limits are regression guards, not targets to fill. Tests should be colocated only while they remain small; large suites belong in a dedicated `tests` child module.

The backend is split by lifecycle responsibility. `backend.rs` owns command routing and top-level service wiring. `backend/state.rs` owns live session and streaming state. `backend/events.rs` projects agent events into that state and persists durable session state. `backend/lifecycle.rs` owns replacement, interruption, compaction, and shutdown. `backend/settings.rs` owns user-facing configuration commands, while `backend/settings_support.rs` contains their pure adapters. `backend/debate_runtime.rs` runs debates and `backend/debate_context.rs` grounds debate subjects in the workspace. `backend/titles.rs` owns session-title generation. `backend/transport.rs` owns bridge envelopes and compact UI-facing tool activity details.

The agent is split between execution and policy. `agent.rs` owns the turn loop and model/tool orchestration. `agent/policy.rs` classifies requests and selects prompts/tools/history. `agent/runaway.rs` detects repeated tool loops. `agent/progress.rs` turns heterogeneous tool results into progress/failure signals. `agent/tool_protocol.rs` normalizes streaming and malformed tool-call formats. `agent/cache.rs` owns prompt-cache boundaries and diagnostics. `agent/context.rs` and `agent/history.rs` own context persistence and history compaction.

The tool registry is likewise a coordinator rather than an implementation bucket. `tools.rs` owns registry state, capability attachment, dispatch, and permission integration. `tools/io.rs` implements workspace/web/document/data reads and Skill scripts. `tools/editing.rs` owns structured edits and workspace evidence invalidation. `tools/shell_runtime.rs` owns shell routing and bounded evaluator calls. `tools/definitions.rs` contains model-facing built-in schemas. `tools/support.rs` contains small stateless argument/schema/range helpers. `tools/paths.rs` owns path-boundary checks and workspace revision fingerprints.

Maintainability comments follow the same rule as the module split: every new module gets a `//!` responsibility note, and non-obvious structs and methods get a short `///` contract explaining what they own or guarantee. Comments should explain responsibility or invariants rather than restating syntax.

Before merging structural work, run `cargo test --all-targets`, `cargo clippy --all-targets -- -D warnings`, and `npm run check` in `RuntimeSource`. The source-layout test is intentionally part of the Rust test suite so architectural regressions fail ordinary CI instead of relying on a separate manual checklist.
